# shibuya — состояние проекта

> Файл для передачи контекста в новый чат. Актуально на **2026-08-06**.
> Рабочие инструкции — в `RUNBOOK.md`, он рядом.

## Что это

Raspberry Pi 5 (Ubuntu 24.04 arm64, hostname `shibuya`) как постоянно доступный
рабочий сервер: заходить с iPhone через Blink Shell по mosh и полноценно работать,
когда нет ноутбука — тушить инциденты в проде, разбирать PR, запускать Claude Code.

Машина стоит дома, но готовится к переезду к родителям, где будет подключена к
ИБП и проброшена с их белого статического IP.

**Ключевая идея:** два независимых канала доступа (Tailscale + проброс портов),
mosh для переживания смены сети, tmux для переживания всего остального.

## Как подключиться

| Откуда | Команда |
|---|---|
| Мак, дома | `mosh -p 60000:60010 shibuya-local` |
| Мак, Tailscale | `mosh -p 60000:60010 shibuya` |
| iPhone | Blink → профиль `shibuya` (mosh, порты `60000:60010`) |

Вход сразу попадает в tmux-сессию `main`. **Выход — `Ctrl-a` затем `d`.**
Если набрать `exit` в последнем окне, он тоже отцепит, а не убьёт сессию
(перехват в `/etc/shibuya/shell-tmux.sh`). Настоящий выход — `builtin exit`.

## Как вносить изменения

Систему руками не трогаем — правим скрипт и раскатываем. Иначе теряется
воспроизводимость, а на ней держится будущая миграция на SSD.

```bash
cd ~/shibuya
./deploy.sh --run              # синхронизировать и прогнать фазу A
./deploy.sh --run --only 20    # один скрипт
./bootstrap.sh --list          # что вообще есть
ssh shibuya '~/shibuya/verify.sh'
```

Всё идемпотентно, повторный прогон безопасен. Оригиналы тронутых системных
файлов — в `/etc/shibuya/backups/`. Репозиторий: `~/shibuya` (git, локальный,
намеренно вне `~/lvn`, чтобы не попасть под git-контекст Skelar).

## Какой SSD купить

Сейчас система на SD-карте (`mmcblk0`, 29 ГБ, занято 7.3 ГБ = 27%). Карта —
расходник: деградирует от записи и через год-два уходит в read-only. Смягчено
(логи ограничены 200 МБ, swap в zram, `noatime`), но не решено.

**Объём: 512 ГБ.** Проверено по ценам (август 2026): 256 ГБ на Розетке стоит
столько же, сколько 512 — дешёвые Kioxia BG4/BG6 на 256 числятся «нет в наличии»,
а реально доступные идут по 3 850–4 823 ₴ против 4 085 ₴ за 512. Экономить на
объёме нечем.

**Обязательно TLC, не QLC.** TLC — 3 бита в ячейке, ресурс ~1000–3000 циклов записи;
QLC — 4 бита и ~300–1000 циклов. При круглосуточной записи логов это разница между
«работает пять лет» и «через полтора года начались странности».

### Список покупки — две позиции, ~4 100–6 100 ₴

**Важно про имеющееся железо:** на Pi стоит официальный корпус Pi 5, у которого
**вентилятор встроен в крышку** (не Active Cooler — радиатора на процессоре нет).
Система это подтверждает: `cooling_fan` крутится 3059 об/мин, температура 56.8°C.
Поэтому вариант с M.2 HAT+ отпадает: HAT занимает место крышки, а снять крышку =
остаться без охлаждения вообще.

| Позиция | Модель | Цена | Где |
|---|---|---|---|
| Корпус + охлаждение + NVMe | **Argon NEO 5 M.2 NVMe** | ~1 550–1 590 ₴ | [Rozetka](https://rozetka.com.ua/ua/443549690/p443549690/) |
| Диск | **500 ГБ, M.2 2280, NVMe, TLC** — модель по цене на момент покупки | ~2 500–4 500 ₴ | [hotline.ua](https://hotline.ua/ua/computer/ssd-nakopiteli/) |

Argon NEO 5 закрывает три покупки одной: алюминиевый корпус, активное охлаждение с
PWM-регулировкой и плата-переходник под NVMe в днище. Дешевле, чем M.2 HAT+ (~900 ₴)
плюс Active Cooler (~560 ₴) по отдельности, и на выходе закрытый корпус, а не голая
плата с этажом сверху. Берёт формат **2280** — самый массовый. Диск соединяется
шлейфом внутри корпуса, внешнего кабеля, который можно задеть, нет.

Нынешний корпус с крышкой-вентилятором остаётся запасным.

**Про выбор диска.** Цены скачут непредсказуемо и формат мало о чём говорит: WD Blue
SN580 500 ГБ (2280) стоил 7 509 ₴, а Transcend 300S 512 ГБ (2230) — 4 085 ₴. Поэтому
модель фиксировать бессмысленно, держаться рамки: **500 ГБ, 2280, TLC, 2 500–4 500 ₴**.

**Kingston NV2/NV3 обходить** — Kingston меняет в этой серии память и контроллер без
смены артикула, что окажется в коробке неизвестно. Для машины, где важен
предсказуемый ресурс записи, плохая лотерея.

**Докупать больше нечего:** блок питания 27 Вт (5.1V/5A) есть, SD-карта остаётся
в слоте как аварийный носитель.

Если попадётся OEM-диск (WD SN740 и подобные выпайки из ноутбуков) — брать только у
продавца с возвратом и сразу проверить пробег:
```bash
sudo apt install -y nvme-cli
sudo nvme smart-log /dev/nvme0n1 | grep -E 'percentage_used|power_on_hours'
```
У нового `percentage_used` = 0%, `power_on_hours` — единицы. Сотни часов = выпайка.

Отвергнутые варианты: **M.2 HAT+ + Active Cooler** (~5 550 ₴, плата без корпуса);
**USB-бокс + SATA SSD** (~3 000–5 300 ₴, дешевле, но внешний кабель как точка отказа
на машине, к которой не подъехать).

### Не переплачивать за скорость

У Pi 5 линия PCIe шириной x1: Gen2 даёт ~450 МБ/с, Gen3 (официально не поддерживается,
обычно работает) ~900 МБ/с. Упирается в шину, а не в диск — Gen4-накопитель не даст
ничего сверх Gen3. Даже нижние ~450 МБ/с против SD-карты это примерно двадцатикратная
разница.

Если диск не определяется — оставить Gen2 по умолчанию, не выставлять
`dtparam=pciex1_gen=3` в `/boot/firmware/config.txt`.

### Питание — уже есть

Официальный **Raspberry Pi 27 Вт USB-C (5.1V ⎓ 5.0A, P1724)** — в наличии, подходит.
Покупать ничего не нужно. Обычная зарядка 5V/3A дала бы случайные перезагрузки под
нагрузкой — худший класс проблем для недоступной машины.

### После установки диска

```bash
sudo rpi-eeprom-config --edit    # BOOT_ORDER=0xf416 — сначала NVMe, потом SD
```
**SD-карту оставить в слоте** как аварийный носитель: при проблемах с NVMe машина
сама свалится на загрузку с неё.

## Что было найдено по дороге (не повторять)

Эти вещи стоили времени и могут всплыть снова:

- **В apt отсутствовал пул `noble-updates`** — только `noble` и `noble-security`.
  apt стоял в неразрешимом конфликте (`bzip2` vs `libbz2-1.0`) и **не мог поставить
  ничего вообще**. Чинится файлом `/etc/apt/sources.list.d/shibuya-updates.sources`.
- **mosh и локаль.** `update-locale LC_ALL=` пишет *пустой* `LC_ALL`, на котором
  mosh-server отказывается стартовать. Плюс macOS шлёт несуществующий
  `LC_CTYPE=UTF-8`; `AcceptEnv` — аддитивная директива, drop-in её не переопределяет,
  поэтому стоковую строку в `sshd_config` пришлось закомментировать.
- **mosh 1.4.0 падает (SIGABRT) при нулевом размере терминала.** Всплывает только
  при headless-тестировании через `script -q /dev/null` на macOS. С настоящим
  терминалом всё работает — не тратить время на «баг».
- **`cmd | grep -q` под `set -o pipefail` врёт при совпадении**: grep выходит первым,
  отправитель ловит SIGPIPE. В `lib/common.sh` для этого есть `contains()`.
- **`write_file` всегда возвращает 0**, факт изменения — через `changed()`.
  Раньше возврат 1 = «без изменений» ронял скрипты на повторном прогоне.
- Официальный apt-репозиторий helm (`baltocdn.com`) отдаёт неполную цепочку
  сертификатов — helm ставится бинарём с `get.helm.sh`.

## Безопасность

На машине креды от трёх GKE-кластеров (два прода) и GitHub-ключи, и она будет
торчать в интернет через проброс.

- Ключи Pi (`id_lvn`, `id_gh`) **отдельные от ключей Мака** — отзываются независимо.
- Ключ клиентского контекста `pt` намеренно **не положен**. Если понадобится:
  `sudo SHIBUYA_WITH_PT=1 ~/shibuya/bootstrap.sh --only 70`
- `gcloud auth application-default login` **не делали** — ADC-токен самая ценная
  вещь на машине, обычного `gcloud auth login` хватает.
- Процедура на случай компрометации — в `RUNBOOK.md`, раздел «Если машину
  скомпрометировали». Написана заранее осознанно.
